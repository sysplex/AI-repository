## 3. 架构与安全契约对照（`CONTRACTS.md`）

对照 `docs/tasks/M8/CONTRACTS.md` 与全局系统契约规范：

1. **分层架构与独立性（Clean Architecture & Layer 2 隔离）**：
   - `app.modules.screener` 稳居业务能力层（Layer 2），严禁反向被基础设施（Layer 3/4）导入；
   - 依赖注入与端口解耦：Screener 与底层 `MarketData`、`Strategy` 及 `AI` 交互全部经由抽象端口（`ports.py`）或公开服务门面（`service.py`），绝无直接底层耦合。
2. **Import-Linter 5 项架构分层契约 100% 保持（5 kept, 0 broken）**：
   - `分层契约：api → 应用服务 → 能力模块 → domain → core`: KEPT
   - `独立契约：marketdata / ai / identity 互不依赖`: KEPT
   - `独立契约（续）：marketdata / ai / identity 不依赖其他业务模块`: KEPT
   - `禁止契约：业务模块只能引用对方的 service / schemas 公开面`: KEPT
   - `禁止契约：路由层不得引用业务模块内部面`: KEPT
3. **100% 代码计算量化防编造防线**：
   - 筛选信号、得分、排名与匹配标的完全由代码计算与策略规则生成（F10），严禁交由 LLM 捏造；
   - 主题股票卡片的财务事实指标严格提取自底层市场数据快照，由 `FactTracingEngine` 严格溯源校验，零幻觉容忍。
4. **高并发信号量与故障隔离**：
   - 执行器内置并发控制（`asyncio.Semaphore`），防止大规模股票池同时计算耗尽系统资源；
   - 单个标的异常通过局部 `try-except` 捕获并记录至 `failed_count`，保证整体筛选批次正常交付。
5. **HARD-01 安全鉴权与多租户隔离**：
   - 17 个 REST API 端点均由 `Depends(get_current_user)` 统一挂载守卫；
   - 自选清单与筛选记录均按 `user_id` 严格隔离，越权访问严格返回 `404 NOT_FOUND`。
