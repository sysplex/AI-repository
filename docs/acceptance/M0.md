## 3. T11 接缝修复登记

按 T11 任务卡第 3 点「可修改 `main.py` 与各任务文件做最小修复」，本阶段仅做一处产品代码修复：

| 文件 | 原因 | 修复 | 验证 |
|---|---|---|---|
| `backend/app/core/logging.py` | uvicorn 0.54.0 用 `uvicorn.access` logger 的 `hasHandlers()` 决定是否输出访问日志；`--no-access-log` 通过清空该 logger 的 handler 并设 `propagate=False` 关闭，但 `setup_logging()` 在应用 import 期把它重新桥接到 root（`propagate=True`），参数被抵消，导致一次请求输出 `uvicorn.access` + `http.access` 两行 | 从 `_BRIDGED_LOGGERS` 移除 `uvicorn.access`；在 `setup_logging()` 中清空其 handler 并设 `propagate=False`，保留应用自身带 `request_id` 的 `http.access` | 本机同版本 uvicorn 复现：`before=2 行 → after=1 行`；runner 步骤 9：`access log lines for one request: 1`，且该行是 `http.access`、不含 `uvicorn.access` |

这使 PR #32 加入的 `--no-access-log` 真正生效，闭环 Issue #26 的验收标准第 2 项（偏差已在 PR #32 与 Issue #26 同步登记）。
