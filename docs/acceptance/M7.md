## 3. 架构与安全契约对照（`CONTRACTS.md`）

对照 `docs/tasks/M7/CONTRACTS.md` 与全局工程规范：

1. **分层架构与独立性（Clean Architecture & Layer 2 隔离）**：
   - `app.modules.research` 位于业务能力层（Layer 2），严禁反向被底层模块（Layer 3/4）导入；
   - 跨模块通信严格遵循最小知识原则，仅通过对方公开的 `ports`、`service` 与 `schemas` 交互。
2. **Import-Linter 5 项架构分层契约 100% 保持（5 kept, 0 broken）**：
   - `分层契约：api → 应用服务 → 能力模块 → domain → core`: KEPT
   - `独立契约：marketdata / ai / identity 互不依赖`: KEPT
   - `独立契约（续）：marketdata / ai / identity 不依赖其他业务模块`: KEPT
   - `禁止契约：业务模块只能引用对方的 service / schemas 公开面`: KEPT
   - `禁止契约：路由层不得引用业务模块内部面`: KEPT
3. **高精度金融量化计算（High-Precision Decimal Accounting）**：
   - 所有标的权重、配置金额、现金比例、分位得分及阈值 100% 采用 `Decimal` 类型，绝对杜绝浮点数精度截断误差。
4. **0 商业 SDK 外部依赖（遵循 TID251 规范）**：
   - `app.modules.research` 内部绝不包含任何第三方 LLM SDK（OpenAI / Anthropic 等）直接引用，所有大模型调用完全通过 Layer 2 的 `AIService` 门面委派。
5. **HARD-01 安全鉴权与多租户隔离**：
   - 所有端点均由 `Depends(current_user)` 统一守卫；
   - 用户审计轨迹与配额扣减严格按租户隔离，杜绝跨租户数据越权访问。
