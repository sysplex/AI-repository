## 3. 架构契约与合规对照（`CONTRACTS.md`）

对照 `docs/tasks/M2/CONTRACTS.md` 进行静态检查与分层测试：

1. **外部库防腐层（Anti-Corruption Layer）**：
   - 依赖隔离：`yfinance` 仅允许在 `app/modules/marketdata/adapters/yfinance.py` 中导入，由 `backend/pyproject.toml` 中的 `[tool.ruff.lint.flake8-tidy-imports.banned-api]` 静态规则强制阻断，任何业务模块或核心层越界直接报错。
   - 异步解耦：YFinance 的所有同步阻塞调用通过 `asyncio.to_thread` 调度至工作线程池执行，坚决不阻塞事件循环。
2. **精度与时间规范**：
   - 金额与价格：一律采用 `Decimal` 类型，数据库存储为 `Numeric(18, 6)`，杜绝浮点数舍入误差。
   - 时区规范：所有时间戳均采用 UTC 时区感知 `datetime`，数据库存储为 `DateTime(timezone=True)`。
3. **架构分层契约（Import-Linter）**：
   - 5 项分层与模块边界契约 100% 遵守：
     - `分层契约：api → 应用服务 → 能力模块 → domain → core`: KEPT
     - `独立契约：marketdata / ai / identity 互不依赖`: KEPT
     - `独立契约（续）：marketdata / ai / identity 不依赖其他业务模块`: KEPT
     - `禁止契约：业务模块只能引用对方的 service / schemas 公开面`: KEPT
     - `禁止契约：路由层不得引用业务模块内部面`: KEPT
4. **统一错误响应模型**：
   - 错误响应严格符合 `{"error": {"code": ..., "message": ..., "details": ..., "request_id": ...}}` 规范。
   - 输入校验失败返回 HTTP 400（`VALIDATION_ERROR`）；外部数据不可用返回 HTTP 424（`DATA_UNAVAILABLE`）。

## 5. 遗留问题与后续里程碑交接建议

1. **真实数据源授权与商业化适配**：
   - 当前内置适配器为 `YFinanceAdapter`（供开发和回测离线回放），由于 Yahoo Finance 条款限制个人非商业使用，后续商业化部署开放给外部多用户前，需按 `DataProvider` 接口扩展适配商业数据源（如 Polygon / Alpaca / Tiingo）。`DataProvider` 协议保证了业务层与存储层无需任何改动。
2. **下游模块接入建议**：
   - **M3（指标与策略引擎）**：通过 `DataService.get_bars(symbol, start, end, interval, adjusted=True)` 获取前复权 K 线进行技术指标计算，避免未来函数。
   - **M4（模拟盘引擎）**：通过 `DataService.get_quote(symbol)` 获取最新撮合价格，依赖缓存与备用降级机制保障盘中稳定性。
   - **M5/M6（AI 核心与事实层）**：直接调用 `DataService.build_facts(symbol, scope)` 生成确定性、防编造的 AI 事实输入，利用 `content_hash` 实现 AI 结果的幂等缓存与审计溯源。
