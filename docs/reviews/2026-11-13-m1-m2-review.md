## 5. 执行顺序与 M5 开工门槛

```
第一批（互相独立，可并行）：HARD-01  HARD-02  HARD-06
第二批（依赖 HARD-01 的限流依赖）：HARD-03
第三批（迁移串行化，严格按序）：HARD-04(0004) → HARD-05(0005) → HARD-07(0006)
任意时间（需外网）：HARD-08
```
- **M5 开工门槛**：HARD-01…05 全部合并。理由：M5 要保存用户的第三方 API 密钥并对其收费类调用设限，必须建立在可靠的鉴权、会话失效与限流之上。
- HARD-06/07/08 不阻塞 M5 的非 M2 部分，但 **HARD-07 必须在 M5 的缓存任务之前合并**。
- 迁移顺序以 `alembic heads` 为准，当前 head 为 `0003_identity`；后合并者必须 rebase 并把 `down_revision` 指向唯一 head。
