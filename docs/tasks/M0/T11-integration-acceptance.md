## 目标
按 `docs/08-test-plan.md §5 的 M0 验收清单` 做端到端验证，修复接缝问题，归档验收记录，打里程碑 tag。

## 范围
**包含**
1. 全新克隆仓库，按 `deploy/README.md` 从零启动，逐项执行 M0 验收清单：
   - `docker compose up` 一条命令启动全栈，`/readyz` 就绪
   - CI 全流程通过（lint/类型/边界/测试/镜像）
   - 配置缺失启动失败并提示具体变量
   - 交易日历 2024–2026 节假日/半日市/夏令时用例通过
   - 迁移可升可降
2. **接缝检查**（CONTRACTS 对照）：逐节核对已合并代码与契约的签名一致，列出偏差表（偏差若合理则更新 CONTRACTS，需协调者批准）。
3. 修复只涉及接缝的小问题（如导入路径、日志字段不一致）；**可修改 `main.py` 与各任务文件做最小修复**，每处修复在验收记录中登记原因。大问题开新 Issue 退回原任务。
4. 全链路冒烟：请求带 `X-Request-ID` 访问 `/healthz`→日志与响应头一致；触发 404/400/500 → 统一错误格式、`request_id` 一致；`/metrics` 有样本；写入一条 `audit_log` 并读回；发布一个领域事件被订阅者收到；`FrozenClock` + 日历联合用例。
5. 性能基线（仅记录，不设门槛）：`/healthz` 与 `/readyz` 的 P95（`k6` 或 `hey`，1 分钟，并发 20）。
6. 安全自检：依赖扫描、镜像非 root、无密钥入库（gitleaks 全历史）、`/metrics` 外部不可达。
7. 输出：
   - `docs/acceptance/M0.md`：逐项勾选、证据、偏差表、基线数据、遗留问题
   - 更新 `CHANGELOG.md`（M0 条目）
   - 更新 `docs/README.md` 的路线图状态（M0 ✅）
   - 打 tag：`m0-foundation-v0.1.0`
   - 在 M1/M2/M5 对应 Issue（如协调者已创建）评论"M0 已完成，可开工"

**不包含**：M1+ 任何功能。
