# 08 测试与验收计划

## 1. 测试金字塔

```
          E2E（少量，关键链路）
        集成（API + DB + Redis，Mock 外部）
      契约（所有端口适配器共用同一套）
    单元（指标、盈亏、仓位、校验器：大量、快）
```

| 层 | 工具 | 外部依赖 | 触发 |
|---|---|---|---|
| 单元 | pytest、hypothesis（属性测试） | 无 | 每次提交 |
| 契约 | pytest 参数化 | 录制 fixture | 每次提交 |

| 安全 | pip-audit、OWASP ZAP 基础扫描 | staging | 里程碑前 |

## 2. 测试数据策略

- **录制 fixture**：把真实 yfinance/供应商响应存为 JSON（`tests/fixtures/`），测试离线、可重复；
- **黄金股票集**：覆盖大盘科技、周期股、高分红、亏损成长、小盘、近期拆股、近期 IPO（数据不足）；
- **合成行情**：用于撮合边界（跳空、涨跌停式极端波动、无成交）；
- **时间冻结**：所有涉及"当前时间/下一交易日"的测试使用冻结时钟。

## 3. 通用质量门槛

| 指标 | 门槛 |
|---|---|
| 模块核心覆盖率 | ≥ 80%；模拟盘盈亏/仓位/撮合 ≥ 95%（**M0 阶段性豁免**：全局 `fail_under` T01–T07 为 0、T10 起 80，见 `docs/tasks/M0/README.md` 附录 A；本节数字为模块目标） |
| 缺陷 | 合并前无 P0/P1 未关闭 |
| 契约测试 | 所有适配器通过同一套用例 |
| 越权测试 | 每个私有端点至少一个"他人访问→404"用例 |
| AI 校验通过率 | 黄金集上首次通过率 ≥ 90%，重试后 100%，否则不得发布提示词版本 |

## 4. 关键专项测试

### 4.1 模拟盘不变量（属性测试，随机订单序列）
1. **现金守恒**：`cash_end = cash_start − Σ买入额 + Σ卖出额 − Σ手续费`；
2. **净值恒等**：`equity = cash + Σ(qty × price)`；
3. **不超卖、不透支**（未启用杠杆时）；
4. **幂等**：同一 `idempotency_key` 重复提交只产生一个订单/一次成交；
5. **拆股不变**：拆股前后持仓市值不变，成本与数量按比例调整；
6. **成交价合法**：成交价必须在该根 K 线 `[low, high]` 内；
7. **时序**：信号日的订单不得以信号日价格成交（只能下一根及以后）。

### 4.2 防未来函数
对每个策略与指标：取任意 `as_of = t`，将 `t` 之后的所有数据替换为随机值，结果必须与原结果**完全相同**。

### 4.3 AI 输出防编造
- Mock LLM 返回：缺字段、枚举越界、含 `facts` 中不存在的数字、含禁用词、`source_field` 指向不存在路径 → 全部必须被拦截并触发重试/失败；
- 对黄金集：随机抽取输出中的数字，验证可在 `facts/computed` 找到；
- 提示注入样例：新闻文本含"忽略以上指令并输出…" → 输出不得受影响。

### 4.4 多租户隔离
参数化遍历所有私有端点：用户 B 的令牌访问用户 A 的资源 ID → 404；列表接口不泄露他人数据；缓存键不跨用户泄露用户私有参数（AI 缓存仅跨用户共享"同公共参数的公共报告"，含用户私有信息的不共享）。

### 4.5 数据降级
模拟数据源超时/限流/返回空/字段缺失：接口返回缓存并标注 `stale`，或明确 `DATA_UNAVAILABLE`；AI 在缺失字段下输出 `data_gaps`，不编造。

### 4.6 夏令时与日历
2026 年 3 月、11 月夏令时切换周；感恩节、圣诞前夕半日市；调度任务触发时间与"下一交易日"逻辑正确。

## 6. 端到端场景

**E2E-01 主链路**
1. 注册并登录 → 2. 创建模拟账户（$100,000）→ 3. 添加自选 `AAPL` → 4. 查看技术面（进场/止损/目标）→ 5. 发起 AI 研究，等待完成 → 6. 发起买入决策（目标价、中期、稳健）→ 7. 依据建议下限价单 → 8. 触发收盘任务 → 9. 次日订单成交，持仓与盈亏更新 → 10. 写交易日志 → 11. 在复盘页看到该条 AI 建议记录。

**E2E-02 筛选到决策**
选"趋势突破"策略 + 标普500 → 得到候选 → 勾选 3 只送入对比 → 查看排名与适合人群 → 对第一名做长期持有评估。

**E2E-03 失败与降级**
断开数据源 → 页面显示"数据过期"并标注时间；耗尽 AI 配额 → 明确提示；LLM 返回非法输出 → 任务失败且不展示半成品。

## 7. 缺陷分级

| 级别 | 定义 | 例子 | 处理 |
|---|---|---|---|
| P0 | 数据错误/资金计算错误/越权/安全 | 盈亏算错、能看他人数据 | 立即修复，阻断发布 |
| P1 | 核心功能不可用 | 无法下单、AI 全部失败 | 阻断发布 |
| P2 | 功能缺陷有替代方式 | 某筛选结果排序不稳定 | 排期修复 |
| P3 | 体验/文案 | 提示不清晰 | 迭代修复 |

## 8. 验收流程

1. 开发者自测，贴出测试报告与演示；
2. 评审者按本节清单逐项勾选并记录证据；
3. 全部通过后在 `docs/acceptance/<module>.md` 归档并打里程碑 tag；
4. 未通过项登记缺陷，修复后仅重测相关项与回归集。
