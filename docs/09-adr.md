# 09 架构决策记录（ADR）

格式：背景 → 决策 → 备选 → 后果。新增决策追加在末尾，已接受的决策不删除，只标记"已被 ADR-xxx 取代"。

---

## ADR-001 模块化单体而非微服务
- **状态**：已接受
- **背景**：小团队、需求仍在演进，需要快速迭代且保留未来拆分空间。
- **决策**：单一代码库、单一部署单元（API 与 Worker 同镜像），内部按模块划分，边界用 import-linter 强制。
- **备选**：微服务（运维与调试成本过高）；无边界单体（后期难拆）。
- **后果**：部署简单；需要纪律维护边界；日后可沿模块边界拆出 Worker/AI 服务。

## ADR-002 端口与适配器隔离外部依赖
- **状态**：已接受
- **背景**：数据源（yfinance 将被替换）、LLM、券商、通知渠道都可能变化。
- **决策**：定义 `DataProvider / Strategy / Broker / LLMClient / Notifier` 端口，外部 SDK 仅出现在 `adapters/`。
- **后果**：替换成本低，可用契约测试保证一致；多一层抽象，需维护接口稳定。

## ADR-003 PostgreSQL 起步，不用 SQLite
- **状态**：已接受
- **背景**：将来多用户并发写入、需要 JSONB、事务与迁移工具。
- **决策**：Postgres + SQLAlchemy 2.x + Alembic；本地开发也用 Docker 里的 Postgres。
- **备选**：SQLite（并发与迁移受限，后期迁移有风险）。
- **后果**：本地需 Docker；开发与生产一致，减少"环境差异"缺陷。

## ADR-004 多租户采用共享库 + `user_id` 行级隔离
- **状态**：已接受
- **背景**：用户规模预计小到中，库级隔离运维成本高。
- **决策**：所有用户私有表含 `user_id`；Repository 基类强制过滤；越权测试自动覆盖所有私有端点；行情等共享数据不带 `user_id`。
- **备选**：每用户一库（运维重）；Postgres RLS（可作为后续加固，v1 先用应用层强制）。
- **后果**：简单高效；依赖代码纪律与测试，后期可叠加 RLS 作为第二道防线。

## ADR-005 AI 只解读，数据与关键数值由代码生成
- **状态**：已接受
- **背景**：LLM 容易编造价格、财务数据，金融场景后果严重。
- **决策**：代码构建 `facts` 与 `computed`，AI 输出需通过 JSON Schema、数字溯源、规则三重校验；止损、目标、配比等数值由代码给出并原样引用。
- **后果**：可信度与可复盘性高；开发量增加（需构建 facts 与校验器）。

## ADR-006 异步任务：Redis + ARQ
- **状态**：已接受
- **背景**：AI 分析、筛选、回测耗时长，不能阻塞请求。
- **决策**：Redis 作为队列与缓存，ARQ（异步原生）执行任务，任务状态入 `tasks` 表，前端轮询或 SSE。
- **备选**：Celery（功能更全但更重）；FastAPI BackgroundTasks（无持久化、无重试）。
- **后果**：轻量；若后续需要复杂编排可迁移至 Celery 或工作流引擎。

## ADR-007 模拟撮合：信号后下一根 K 线成交
- **状态**：已接受
- **背景**：避免用未来信息成交造成虚高收益。
- **决策**：市价单按下一根 K 线开盘价加滑点；限价/止损按 K 线高低价规则判定；回测与模拟盘共用同一撮合逻辑。
- **后果**：结果更保守可信；日线级别无法模拟盘中细节，已在文档中声明。

## ADR-008 金额使用 Decimal，时间使用 UTC + 美东业务时区
- **状态**：已接受
- **决策**：资金计算禁用 float；数据库 `NUMERIC(18,6)`；存储时间 UTC，交易日与调度基于 `America/New_York` 与 NYSE 日历，统一经 `core.calendar`。
- **后果**：避免精度与夏令时缺陷；需要在序列化时用字符串传输金额。

## ADR-009 认证：JWT 短期访问令牌 + 可吊销刷新令牌
- **状态**：已接受
- **决策**：access 15 分钟；refresh 存哈希可吊销；密码 argon2；预留 OAuth/二步验证。
- **备选**：服务端 Session（需要粘性或共享存储，当前可行但与前后端分离不够灵活）。
- **后果**：无状态扩展容易；需要妥善处理令牌存储（前端避免 XSS 暴露）。

## ADR-010 文档即代码：Markdown + Mermaid，随仓库评审
- **状态**：已接受
- **决策**：设计文档放 `docs/`，图用 Mermaid；接口/表/提示词变更必须在同一 PR 更新文档。
- **后果**：文档与代码同步；无需额外工具；复杂图表表达力有限时可附 PNG/SVG。

## ADR-011 数据源策略：yfinance 起步，开放前换授权源
- **状态**：已接受（附约束）
- **背景**：yfinance 非官方、条款限制个人使用，不适合向第三方用户提供服务。
- **决策**：v1 自用/内测期间使用 yfinance；**对外开放前必须切换到有再分发授权的数据源**（Polygon/Tiingo/Alpaca 等），通过 `DataProvider` 适配器完成。
- **后果**：开放前增加一次数据源迁移与契约回归；在 README 的上线门槛中跟踪。

## ADR-012 数据库访问：SQLAlchemy 2.x 异步 + asyncpg
- **状态**：已接受
- **背景**：FastAPI 与 ARQ 均为异步原生，IO 密集（数据源、LLM、数据库）。
- **决策**：全程异步 `AsyncSession` + `asyncpg`；Alembic 使用异步 env；业务代码不得在事件循环中执行阻塞调用（CPU 密集计算放线程池/进程池）。
- **后果**：吞吐好；测试需 `pytest-asyncio`；开发者需注意异步陷阱。

## ADR-013 依赖与工具链：Python 3.12 + uv + pyproject
- **状态**：已接受
- **决策**：`uv` 管理依赖与锁文件（`uv.lock` 入库）；工具统一配置在 `backend/pyproject.toml`；选择依赖版本时避开发布不足 14 天的版本。
- **后果**：环境可复现；所有开发者（含 AI Agent）用同一命令集（`make check`）。

## ADR-014 交易日历：exchange_calendars（XNYS）
- **状态**：已接受
- **决策**：以 `exchange_calendars` 的 XNYS 日历为基础，封装在 `core.calendar`；其余代码禁止直接引用该库。测试用例以 NYSE 官方休市/提前收盘公告交叉验证。
- **后果**：节假日与半日市由成熟库维护；需注意库默认日期范围，初始化时显式指定 2020–2030。
